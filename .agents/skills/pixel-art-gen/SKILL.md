# Pixel Art Generation

목표는 픽셀처럼 보이는 고해상도 그림이 아니라, 명시된 저해상도 원본에서 픽셀 하나씩 통제되는 **트루 픽셀 에셋**이다. 모든 신규 픽셀 아트와 픽셀 아트 수정에 적용한다. 기존 고해상도 에셋은 자동으로 변환하거나 적합 판정하지 않는다.

## 그리드 계약

그리드는 **네이티브 픽셀로 된 제작 단위**다. 확대된 한 픽셀의 크기, PNG 저장 배율, 아틀라스 프레임 수와 구분한다. 1 네이티브 픽셀이 최소 표현 단위이며 모든 좌표는 그 픽셀에 맞춘다.

| 규격 | 한 칸 | 용도 |
| --- | --- | --- |
| Grid A | 8×8px | 작은 아이콘, 단순 장식과 디테일 |
| Grid B | 16×16px | 캐릭터, 아이템 등 세부 묘사가 필요한 에셋 |
| Grid C | 32×32px | 더 많은 픽셀을 배정하는 고품질·고밀도 에셋 |

캔버스는 선택한 그리드의 정수 칸 수로 지정한다. 예: B 6×8칸 = 96×128 네이티브 픽셀. C가 자동으로 더 좋은 그림을 뜻하지 않는다. 같은 장면의 에셋 사이 픽셀 밀도를 임의로 바꾸지 않으며, 복잡한 배경도 필요한 칸 수를 늘려 설계한다.

사람형 NPC의 애니메이션 출력은 [human-character-gen](../human-character-gen/SKILL.md)의 공통 규격 **B 8×10칸 = 128×160, 발 기준점 `(64,140)`**을 따른다. 위 96×128 예시는 일반 그리드 설명이며 NPC 애니메이션 출력 규격이 아니다.

제작 전에 그리드, 칸 수, 네이티브 크기, 팔레트/최대 색 수, 기준점, 레이어, 표시 배율, 참조의 역할을 기록한다. 기존 계약은 재사용한다. 사람 캐릭터 크기·레이어는 [human-character-gen](../human-character-gen/SKILL.md)을 따른다.

## 실제 픽셀 규칙

- 원본은 네이티브 크기의 RGBA PNG. 확대 미리보기와 게임용 내보내기를 원본과 구분한다.
- 좌표·마스크·피벗·이동은 정수 픽셀. 회전/변형은 해당 프레임을 픽셀 단위로 정리한다. 보간 회전 결과를 그대로 쓰지 않는다.
- 확대는 정수 배율의 nearest-neighbor만 사용한다. 기본 미리보기는 4배. 런타임에서도 nearest sampling, 픽셀 정렬과 정수 표시 배율을 확인한다.
- 외곽선/색 경계에 자동 안티앨리어싱, 블러, 그라데이션, 반투명 테두리, 리샘플링 중간색을 넣지 않는다. 기본 알파는 0 또는 255. 반투명이 필요한 연기·빛 등은 별도의 효과층과 계약으로 구분한다.
- 기본 팔레트 상한은 에셋/캐릭터 전체 합계 불투명 RGB 32색. 작은 A 아이콘은 16색 이내를 우선한다. 더 필요하면 생성 전에 상한과 이유를 기록한다. 레이어마다 32색씩 따로 배정해 전체 색 수를 늘리지 않는다.
- 기존 원본을 맞추는 작업에서는 원본의 재질/얼굴 명암과 정체성을 먼저 보존한다. 32색은 새 작업의 시작값이며 참조의 디테일을 깎는 강제 제한이 아니다. 필요하면 공유 팔레트를 64색 등으로 명시해 늘리고, 전신을 먼저 축소·양자화해 얼굴 특징을 잃지 않도록 얼굴 영역을 따로 검수한다.
- 외곽선은 네이티브 **1px로 유지한다**. 확대 미리보기의 굵기가 아닌 네이티브 기준이다. 외곽선 색을 두껍게 쌓아 그림자로 사용하지 않는다. 그림자는 재질별 별도 색으로 표현한다. 외곽선과 내부 그림자가 합쳐진 검은 띠, 이중 윤곽선, 굵은 검은 쐐기를 정리한다. 눈동자처럼 본래 짙은 색 면인 요소를 외곽선으로 오인해 얇게 만들지 않는다.
- 외곽선 굵기와 색의 명도를 별도로 관리한다. 검정에 가까운 윤곽·목깃·의상 겹침·장비 경계는 짙게 유지한다. 내부의 검은 픽셀을 전부 그림자로 간주해 밝게 치환하지 않는다. 사용자에게 승인받은 얼굴/표정은 몸의 경계를 정리하는 과정에서 다시 바꾸지 않는다.
- 겹침 경계와 재질 디테일에 일괄 침식·세선화·명도 치환을 적용하지 않는다. 버클, 가죽 두께, 옷 주름, 손/장갑의 경계가 손상될 수 있다. 1px 규칙을 이유로 의도된 원본의 선·색 면을 자동으로 없애지 말고, 필요한 부분을 국소적으로 정리해 비교한다.
- 대각선은 의도된 계단과 큰 색 클러스터로 표현한다. 머리카락/천/금속 표면에 불필요한 고립 픽셀, 톱니 모양 잔가닥, 자동 노이즈를 넣지 않는다.
- 기존 시리즈의 팔레트, 광원, 외곽선 색, 픽셀 밀도를 유지한다. 새 시리즈는 기본 좌상단 광원으로 시작할 수 있으나 참조의 광원을 우선한다.

## 제작 흐름

1. 참조를 **정체성/비율**, **화풍/팔레트**, **표정/동작** 역할로 나눈다. 사용자가 좋아한 기존 표정은 동작 참조로 보존하되, 잘못된 체형이나 눈 비율까지 복사하지 않는다.
2. 한 개의 기준 에셋부터 만든다. 사람 캐릭터는 중립 포즈와 레이어 합성본을 먼저 검수한다. 기준이 어긋난 상태에서 시트 전체를 생성하지 않는다.
3. 래스터 생성/편집에는 사용 가능한 imagegen 스킬과 이미지 생성 도구를 따른다. 프롬프트에 네이티브 크기, 팔레트, 투명도와 고정할 형태를 명시하되 도구가 정확한 해상도/정렬을 보장한다고 가정하지 않는다.
4. 고해상도 생성 결과는 **후보/참조**로 취급한다. 네이티브 그리드에 재구성하고 팔레트·알파·계단·작은 형태를 정리한 뒤 검수한다. 단순 축소, 색 양자화, 알파 임계값 처리만으로 픽셀 아트 품질이나 원본 일치가 확보됐다고 보고하지 않는다. 자동 처리 후 눈·수염·손·외곽선 손실을 확인한다.
5. 네이티브 1배, nearest 4배, 참조와 같은 가시 높이의 비교본을 확인한다. 투명층은 밝고 어두운 단색 배경 모두에 합성한다. 뷰어가 보여주는 투명 영역의 RGB를 실제 배경으로 오인하지 않는다.
6. 아래 검증기로 구조를 검사하고, 시각 검수로 클러스터·가독성·비율·일관성을 확인한다. 구조 검사만으로 화풍이나 정체성 일치를 선언하지 않는다.
7. 검수된 네이티브/레이어를 보존해 기계적으로 패킹한다. 프레임별 자동 크기 맞춤, 서로 다른 축척, 비정수 축척을 적용하지 않는다. 기존 런타임 규격과 다르면 변환/코드 변경 범위를 설명하고, 에셋 요청을 이유로 런타임을 임의 재설계하지 않는다.

두 번 연속 같은 정체성/그리드 오류를 반복하면 같은 시트의 재생성을 중단하고 한 포즈/레이어로 작업을 줄여 수정한다. 정확한 제작이 불가능하면 후보를 완성품으로 덮어쓰지 말고 한계를 보고한다. 별도의 승인 절차를 만들 필요는 없다.

## 구조 검증

Pillow가 필요하다. 환경에 없으면 `uv run --with pillow`로 실행할 수 있다. RTK 규칙이 있는 작업 환경에서는 명령에 그 규칙도 적용한다.

```sh
python .agents/skills/pixel-art-gen/scripts/validate_pixel_asset.py path/to/native.png --grid B --cells 6 8 --max-colors 32
```

`--preview path/to/preview-4x.png --scale 4`를 추가하면 정확한 nearest 정수 확대인지도 검사한다. 검증기는 이미지를 수정하지 않으며, 치수·RGBA·이진 알파·색 수·확대 일치만 확인한다. 반투명 효과는 별도 계약에 맞춰 검사한다. 아틀라스는 단일 프레임 크기 대신 시트 전체의 그리드 칸 수를 전달한다.

## 산출물

기존 경로 관례를 따르며 네이티브 원본, 필요한 레이어/프레임, 그리드·팔레트·피벗·프레임 순서 메타데이터, 비교 미리보기를 남긴다. 참조와 최종 프롬프트를 기록하고 후보/채택본을 구분한다. 기존 파일 교체는 사용자가 요청한 범위에 한정한다.
