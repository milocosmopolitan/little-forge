# 아이템 체계

[홈](../../README.md) · [재료](MATERIALS.md) · [제작물](CRAFTABLES.md) · [소비품](CONSUMEABLES.md)

아이템은 재료를 얻고, 도구를 만들고, 주민과 거래하며 대장간을 성장시키는 연결점이다. 아래 데이터 규칙은 구현 설계안이다.

## 분류

| 분류 | 의미 | 주된 이동 |
|---|---|---|
| 재료 | 제작·수리·연구에 투입 | 상점/탐험 → 인벤토리 → 작업 |
| 제작물 | 무기·생활 도구·중간 가공품 | 작업 → 진열/납품/다음 제작 |
| 소비품 | 음식·탐험 보급 | 구매 → 적용/파견 시 소비 |
| 시설·가구 | 대장간에 설치하는 영구 투자 | 목공소 → 대장간 |
| 작업 장비 | 대장장이가 사용하는 장갑·앞치마 등 | 가죽세공소 → 장비 |
| 카드 | 장착 또는 제작 각인 자원 | 별도 [카드 체계](../cards/README.md) |

카드 그림으로 표현되는 일반 아이템과 실제 카드 시스템을 구분한다. 아이템을 카드 모양으로 표시한다고 카드 합성 대상이 되지 않는다.

## 정의와 인스턴스 — 설계안

정적 정의는 item_id, 분류, 표시명, 설명, 아트 참조, 쌓기 정책, 구매/판매 가능 여부를 가진다. 진행 상태는 수량, 소유 위치, 예약 수량을 가진다. 개별 무기의 품질·각인이 필요해질 때만 인스턴스 ID를 도입한다.

- 기본 가격과 현재 견적을 분리한다. 호감도는 거래 시 계산한다.
- 레시피·상품·의뢰는 표시명이 아닌 ID로 아이템을 참조한다.
- 도구 ID와 수리 의뢰 ID를 구분한다. 수리 의뢰가 도구 소유권을 부여하지 않는다.
- 의뢰용 도구를 진열 판매하거나 다른 의뢰에 중복 납품할 수 없게 예약한다.
- 재고·시설 설치·캐릭터 장착·탐험 보급은 서로 다른 소유 위치로 표현한다.

## 인벤토리와 크기

장면 32×32, 상세 64×64, 카드 128×128의 아트 방향이 논의되었다. 이후 단검 설계에는 96px 기준 슬롯·가변 크기·3티어가 사용되었다. 이 둘은 그대로 하나의 최종 규격으로 합칠 수 없다.

**확정 방향:** 모든 단검을 강제로 1×2 슬롯에 넣지 않는다. 3티어보다 높은 무기는 별도 유니크 디자인·아트팩으로 접근할 수 있다. 무료 3D 에셋 활용을 우선한다.

**미정:** 최종 인벤토리 슬롯 기준, 내보내기 해상도, 슬롯 크기별 가방 제약. UI에서 96px/128px를 검증한 뒤 아트 메타데이터와 함께 고정한다. 해상도를 아이템 성능이나 희귀도와 동일시하지 않는다.

## 장비와 외형

작업 장비는 영구 효과, 음식은 소비 효과로 구분한다. 초기에는 기존 남녀 대장장이 애니메이션을 활용한다. 장비마다 모든 프레임을 다시 만드는 방식 대신 효과와 제한된 액세서리 표시부터 검증하는 설계안이다. 전체 의상 레이어 시스템은 후속이다.

## 데이터 검증 기준

정의되지 않은 재료·레시피 참조, 음수 재고, 예약량 초과 소비, 존재하지 않는 아트 참조를 검출한다. 아이템 추가 시 획득처·소비처·가격 근거·연구 연결·MVP 포함 여부를 함께 기록한다. 구체 수치가 없다는 이유로 임의의 제작법이나 희귀도를 확정하지 않는다.
