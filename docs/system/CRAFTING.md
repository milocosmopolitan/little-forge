# Crafting — 제작·수리

[홈](../../README.md) · [제작물](../items/CRAFTABLES.md) · [경험](EXPRIENCE.md) · [관계](NPC_RELATIONSHIP.md)

## 중심 활동

| 활동 | 목적 | 결과 |
|---|---|---|
| 일반 제작 | 무기·도구 공급 | 제작물·성장 경험 |
| 수리 | 주민 도구를 다시 사용할 수 있게 함 | 주수입·관계·피드백 자격 |
| 신규 도구 의뢰 | 개선 도구 공급 | 성장 보상·상점 해금 조건 |
| 제련 | 재료 가공 | 구체 단계·시설은 미정 |
| 연구 | 새 제작법·기술 발견 및 완성 | 별도 진행 상태 |

**확정:** 수리는 주된 수입 퀘스트이며 납기가 있다. 도구가 실제로 닳는 시뮬레이션은 만들지 않는다. 수리 템플릿이 “손상된 톱날” 같은 상황을 제공하면 충분하다.

## 제작 준비 — 설계안

레시피를 선택하면 재료·사용 가능 재고·작업 시간·연구 조건·결과·연결 의뢰를 보여준다. 부족한 재료는 관련 상점이나 탐험 정보로 이어진다.

카드는 선택적인 후속 시스템이다. [특전](../cards/PERK_CARDS.md)은 장착 효과, [강화](../cards/ENHANCE_CARDS.md)는 제작 시 소비하는 각인 방향으로 설계한다. 기본 제작이 카드 도입에 종속되지 않게 한다.

## 작업 상태

| 상태 | 의미 | 자원 처리 제안 |
|---|---|---|
| 등록 전 | 견적·조건 조회 | 소비 없음 |
| 대기 | 작업 큐에 등록 | 재료 예약 |
| 작업 중 | 논리 작업 시간 진행 | 시작 시 재료 소비 |
| 완료 | 결과 생성·성장 처리 | 결과·경험 한 번 지급 |
| 취소 | 작업 중단 | 시작 전 예약 해제, 시작 후 정책 미정 |

등록 시 예약·시작 시 소비는 **설계안**이다. 실제 소비 시점을 바꾸면 카드·의뢰·취소·저장 정책도 함께 갱신한다.

작업 완료와 의뢰 납품은 별개다. 수리 작업 완료 결과는 원래 의뢰와 연결하고, 일반 재고에서 같은 도구를 중복 생성하지 않는다. 신규 제작물은 지정 의뢰에 예약하거나 일반 재고로 들어가도록 목적을 구분한다.

## 큐와 우선순위

플레이어는 기존 무기 제작과 주민 수리 중 우선순위를 선택한다. 제작 큐의 크기·동시 작업 수·중단과 재개·순서 변경 정책은 미정이다. 안전한 초기 구현은 시작 전 대기 작업의 순서 변경부터 검토한다.

자동 수리 수락·우선 배정은 필수 확정 기능이 아니다. 납기 정책과 재료 소모가 검증된 뒤 제공한다. 작업 장비의 큐 +1 같은 효과도 예시이며 기본 큐 크기 확정으로 해석하지 않는다.

진행 바·망치 애니메이션은 논리적 작업 시간을 표시한다. 프레임 드롭·창 축소·백그라운드 처리로 결과가 달라지지 않도록 한다.

## 수리와 납품

1. 의뢰 조건과 보상을 확인하고 수락한다.
2. 필요한 재료를 구매하거나 탐험으로 확보한다.
3. 수리 작업을 의뢰 ID와 연결해 큐에 등록한다.
4. 작업을 완료한다.
5. [관계 문서](NPC_RELATIONSHIP.md)의 납품 정책으로 계약을 완료한다.
6. 골드·호감도·성장 및 피드백 자격을 기록한다.

자동 납품은 설계 후보다. 플레이어가 결과 창을 늦게 읽었다는 이유만으로 납기 실패하지 않도록 완료·납품·수령의 시각 의미를 확정해야 한다.

## 성장과 연구

제작 중 이해도가 확률적으로 상승하고 관련 연구를 발견하는 방향을 따른다. 튜토리얼 3개 주문의 이해도 Lv.1 보장을 유지한다. 제작 경험의 확정 지급·이해도의 실패 보정은 [경험 문서](EXPRIENCE.md)의 설계안이다.

NPC 사용 피드백은 납품 이후 시간 이벤트로 발생한다. 수리 완료 즉시 같은 피드백을 무한 지급하지 않는다. 연구를 발견해도 완료 조건을 충족하기 전에는 새 레시피를 사용할 수 없다.

## 판매 연결

진열품을 방문객이 구매하면 재고 감소와 골드 증가를 한 번 적용한다. 구매·무기 소지 퇴장 연출은 상태 변경의 결과다. NPC가 퇴장하는 애니메이션을 다시 재생해도 판매 보상이 반복되지 않게 한다.

의뢰에 예약된 제작물은 자동 판매하지 않는다. 판매 가격·수요·방문 빈도는 미정이며 복잡한 시장 시뮬레이션을 전제하지 않는다.

## 검증 기준

재료 부족 시 등록 거부, 이중 예약·음수 재고 방지, 완료/취소 경계의 일관성, 의뢰별 결과 연결, 진열품과 납품품 분리, 보상 1회, 저장/복귀 후 큐 복원, 납기와 작업 시계의 일관성을 검증한다.

제작 성공률·품질 분포·재료 손실·실패 페널티·제련 연료·각인 실패는 미정이다. 수치나 처벌을 합의 없이 확정하지 않는다.


## 피로도와 작업 속도 (확정 방향)

[NEEDS](NEEDS.md)의 대장장이 피로가 높아질수록 제작 속도는 감소한다. 수면으로 피로를 줄이며, 음식·음료는 각각 허기·갈증을 회복하여 피로 누적 가속을 완화한다. **허기·갈증으로 작업 속도를 별도 중복 감속하지 않는다**는 초기 설계안을 따른다.

피로 속도 반영은 프레임마다 불안정하게 재계산하지 않고 시뮬레이션 시간 경계에서 결정적으로 처리한다. 이미 완료된 아이템을 소급 변경하지 않으며, 최대 피로에서도 무료 우물물·기초 음식·수면으로 회복 가능한 루프를 보장해야 한다. 실제 수치와 수면/자동 섭취 정책은 미정이다.

## 미지 무기 발견형 수리 — 합의된 확장 (2026-10-15)

[DISCOVERY_REPAIR](DISCOVERY_REPAIR.md)를 따른다. 낯선 무기를 가져온 방문객의 수리 의뢰에서 플레이어는 거절/일반 수리/연구 수리 중 선택한다. 연구 수리는 시간이 늘어나 납기 실패와 보수/호감도 손실 위험이 있지만, 작업 중 얻은 구조·재료·제련 연구 단서는 실패하더라도 보존한다. 수탁 물품 분해·판매를 금지하고 소유 아이템 Salvaging만 기본 허용한다. Enhance는 퀘스트·수리·Salvaging에서, Perk는 경험·연구를 통해 얻는다.
