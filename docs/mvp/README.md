# MVP 범위와 개발 단계

[홈](../../README.md) · [아키텍처](../../ARCHITECTURE.md)

핵심 목표는 다른 일을 방해하지 않는 작은 대장간이다. 먼저 플랫폼 기반과 최소 반복을 검증하고, 최신 합의인 마을 수리 경제를 콘텐츠 MVP에 연결한다. 문서가 존재하는 모든 기능을 첫 빌드에 넣지는 않는다.

## 1. Foundation POC

**확정 방향:** Godot 우선·하단 플로팅 창·Rust 점진 도입·Windows/macOS/Linux·Steam 목표.

| 항목 | 검증 결과로 남길 것 |
|---|---|
| 하단 창 | 위치·배율·다중 모니터·확장/축소 |
| 투명도·입력 통과 | 실제 조작 영역, 통과 해제 및 복귀 수단 |
| 작은 장면 | 대장장이 반복 작업·방문객·판매 후 퇴장 |
| 최소 상태 | 제작 1종·재료·골드·한 번의 판매 |
| 저장 | 재시작 복원·손상 복구·시간 처리 |
| Rust 경계 | 도입 시 Godot와 명령/결과 왕복, 규칙 중복 없음 |
| 성능 | 활성/백그라운드/패널 열린 상태 측정 |

카드·전체 연구 트리·60종 무기·완전한 마을 패널·에셋 생성기는 POC의 완료 조건이 아니다.

## 2. 콘텐츠 MVP의 확정 범위

| 영역 | 포함 |
|---|---|
| 경제 | 수리 주수입, 신규 도구 의뢰, 무기 진열 판매 |
| 상주 NPC | 목수·가죽세공사·농부 |
| 고유 도구 | 각 3종, 총 9종 |
| 성장 상품 | 각 상점 1종, 총 3종 |
| 의뢰 생성 | 30~60분 간격 시간 이벤트 |
| 관계 | NPC별 0~100, 납기 성공/실패 및 가격 변화 |
| 피드백 | 사용 후 보고 → 이해도·연구 경험 |
| 상점 | 목공소 가구·재료 / 가죽세공소 장비·재료 / 농장 보급 / 주점 음식·모집 |
| 대장간 | 제작·수리·연구·진열과 의뢰함 |
| 탐험 | 필요한 재료를 확보하는 활동, 파견 중심으로 구체화 |

고유 도구 9종과 성장 상품 3종의 **수량**은 확정이다. 개별 이름은 [제작물](../items/CRAFTABLES.md)의 콘텐츠 초안이다. 방문 NPC는 존재하되 직업별 깊은 연구·성장 트리는 확장 범위다.

## 3. 시작용 조정값과 미정 사항

| 항목 | 현재 위치 |
|---|---|
| 일반 수리 납기 2시간 / 신규 제작 4시간 | 조정값, 수락 후 시작 제안 |
| 미수락 3건 / 진행 2건 | 대기 폭주 방지 조정값 |
| 수리/신규 제작/피드백 60/20/20 | 이전 제안. 확정 비율 아님; 피드백 자격과 분리 필요 |
| 피드백 5~8종 / 발견 3~4개 | 소규모 콘텐츠 검증 제안 |
| 호감도 60 + 특정 도구 납품 | 상품 해금 조건의 조정 예시 |
| 목공소 가구 3종 / 장비 3종 / 주점 음식 3종 | 상점 패널 초안의 시작 수량 |
| 무기 MVP 개수·탐험 지역 수·파견 시간 | 미정, 최소 반복 검증 후 결정 |
| 오프라인 상한·납기 시계·자동 납품 | 아키텍처/관계 문서의 설계안 |
| 카드 첫 도입 시점 | 파운데이션 이후, 콘텐츠 MVP 필수 여부 미정 |

## 4. 확실한 제외 범위

- 도구 내구도 감소·파손의 물리 또는 생산량 시뮬레이션.
- NPC 직업 숙련도와 상점 생산력의 다단계 시뮬레이션.
- 씨앗 심기·가축 관리 등 농장 경영.
- 초기 제품을 자체 엔진·대규모 무기 제작 도구 개발로 확대.
- 파운데이션에서 카드 뽑기·합성·온라인 거래·멀티플레이.
- 직접 이동·직접 전투는 초기 구현 범위에 넣지 않는 설계안. 재료 수집은 우선 탐험 파견으로 표현한다.

## 5. 플레이 검증 시나리오

1. 처음 실행하면 작은 대장간에서 자동 작업을 관찰한다.
2. 주민 주문 3개를 완료하고 관련 이해도 Lv.1을 보장받는 튜토리얼 방향을 검증한다.
3. 수리 의뢰를 수락하고 부족한 재료를 상점에서 구매한다.
4. 제작·수리를 큐에 넣고 다른 일을 하다가 결과를 확인한다.
5. 납품으로 골드·호감도를 얻는다. 수동 수령 지연만으로 손해가 발생하지 않는지 검증한다.
6. 관련 도구를 새로 제작해 NPC에게 공급한다.
7. 사용 피드백이 장부에 기록되고 연구가 진행된다.
8. 해금 상품을 상점에서 구매해 대장간 성장에 사용한다.
9. 주점에서 탐험가를 모집하고 보급 후 파견하여 재료를 회수한다.
10. 종료·절전·복귀 후 진행과 재고·보상이 일관되게 복원된다.

튜토리얼은 30~60분의 첫 이벤트를 기다리지 않도록 별도 시작 주문을 제공하는 설계안이다. 이후 정상 이벤트 간격을 적용한다.

## 6. 콘텐츠 MVP 완료 기준

- 9종 도구가 올바른 NPC·레시피·피드백과 연결된다.
- 세 상점 모두 수리 → 관계 → 신규 도구 → 상품 해금 흐름을 체험할 수 있다.
- 의뢰는 수락 전 납기를 소비하지 않고, 실패·거절·미확인이 구별된다.
- 의뢰가 쌓여도 알림과 방문이 플레이어를 계속 붙잡지 않는다.
- 재료 구매와 탐험 중 선택할 이유가 있고, 수리로 재료비 이상의 진행이 가능하다.
- 연구 기회 발견과 실제 연구 완료가 구별된다.
- 저장/복귀/중복 입력으로 재료나 보상이 복제되지 않는다.
- 모든 시작 콘텐츠의 미정 수치가 데이터로 조정 가능하다.

플레이 가능성과 성능·플랫폼 검증이 출시 판단의 근거다. 위 내용은 완료 보고가 아니라 목표다.


## 이전 결정 복구 — 서사·튜토리얼·아이템 단계

- [게임 서사](../system/STORY.md): 평화로운 마을 도구 장인이 던전 몬스터 출몰 이후 방어용 무기를 제작하게 되는 동기. 기초 공방 설비 보유 시작.
- [튜토리얼](TUTORIAL.md): 주민 주문 3회 내 해당 이해도 Lv.1 보장. 구체 주문/등장 순서는 제안과 확정을 구별.
- [무기와 첫 제작 콘텐츠](../system/WEAPONS.md): 장기 코어 무기 60종×3 시각 티어와 첫 플레이 가능 빌드의 최소 품목은 별개. 초기 8개 예시는 후보이며 3개 상점 9도구는 콘텐츠 MVP 확정 축.
- [연구](../system/RESEARCH.md): 무기 구조·재료·제련 기술 교차 및 발견형 연구.
- [허기·갈증·피로](../system/NEEDS.md): 자동 수면과 기상 후 음식 창고 자동 섭취, 무료 우물물. 파운데이션 창 기능의 필수 게이트로 확대하지 않는다.

**기술 방향 최신 결정:** Bevy / Pure Rust, macOS 우선, Windows Shadow PC 수동 데스크톱 QA, 관리 패널은 창 위쪽으로 확장. [플랫폼 QA](../system/PLATFORMS.md), [결정 감사](../system/DECISION_AUDIT.md)를 우선한다. 이 문서의 기존 Godot/POC 표현은 레거시이며 Astra 진행 중인 스캐폴드 문서 정리와 함께 후속 갱신한다.
