# Little Forge

데스크톱 하단의 작은 대장간에서, 마을 주민의 도구를 고치며 함께 성장하는 방치형 게임.

다른 일을 하는 동안에도 대장장이는 제작하고 손님은 방문한다. 플레이어는 가끔 돌아와 의뢰의 우선순위를 정하고, 재료를 주문하고, 탐험대를 보내며 다음 성장을 선택한다. TaskbarHero처럼 데스크톱 위에서 작게 지속되는 경험이 출발점이다.

> 기획 기준일: 2026-10-15. 현재 저장소는 설계 문서 단계이며 실행 가능한 게임·빌드·테스트는 아직 없다. 아래 기술 구조는 구현 목표다.

## 핵심 경험

**수리 의뢰 → 재료 확보 → 제작·납품 → 골드와 호감도 → 사용 피드백 → 이해도와 연구 → 새 도구·상점 상품 → 대장간 성장**

- 수리는 마을 주민과 관계를 맺는 주된 수입 활동이다.
- 신규 도구 납품은 상점 상품을 해금하는 성장 의뢰다.
- 무기 제작과 진열 판매는 방치 수익 및 탐험 경제와 연결된다.
- NPC는 구매자이자 재료 공급자이며, 제작한 도구를 평가하는 협력자다.
- 의뢰 사이에는 상점 거래·연구·탐험을 선택할 여유를 둔다.

## 결정 사항과 문서 읽는 법

| 표시 | 의미 |
|---|---|
| **확정** | 사용자와 합의한 방향·제약 |
| **설계안** | 구현을 구체화하기 위한 제안. 승인된 결정으로 취급하지 않는다 |
| **조정값** | 플레이테스트에서 바꿀 수치·콘텐츠 초안 |
| **미정** | 근거가 부족하거나 후속 결정이 필요한 항목 |

최신의 명시적 결정을 우선한다. 초기에 논의한 대규모 무기·카드·연구 콘텐츠는 장기 설계에 보존하되, 파운데이션 검증의 필수 범위로 확대하지 않는다. 개별 문서는 이 구분을 따른다.

## 확정된 기반

| 영역 | 방향 |
|---|---|
| 제품 | 가벼운 데스크톱 방치형 대장장이 게임, Steam 출시 목표 |
| 화면 | 데스크톱 하단 플로팅 창, 필요할 때 관리 화면 확장 |
| 엔진 | Godot 우선, Rust 코어 점진 도입 |
| 플랫폼 | Windows·macOS·Linux 지원 목표, 플랫폼별 POC 검증 필요 |
| 마을 경제 | 목공소·가죽세공소·농장과 양방향 거래 및 수리 의뢰 |
| 이벤트 | 30~60분 간격의 시간 기반 의뢰 이벤트 |
| 도구 | 위 세 상점 각각 고유 도구 3종, 해금 상품 1종 |
| 관계 | NPC별 호감도 0~100, 납기 결과가 관계와 가격에 영향 |
| 성장 | 제작·수리와 실사용 피드백이 이해도·연구로 연결 |
| 제외 | NPC 도구 내구도·물리 시뮬레이션, 복잡한 상점 생산 시뮬레이션 |

## 마을과 화면

| 장소 | 주요 역할 |
|---|---|
| 대장간 | 제작·수리 큐, 연구, 진열·판매, 의뢰함 |
| 목공소 | 가구·목재·손잡이 구매, 도구 의뢰 |
| 가죽세공소 | 작업 장비·가죽 구매, 도구 의뢰 |
| 농장 | 식량·기초 보급 구매, 농기구 의뢰 |
| 주점 | 음식 구매·탐험가 모집 |
| 마을 밖 | 탐험 준비·파견·귀환 결과 |

지도에서 선택 가능한 지점은 8개라는 아트 요구가 있다. 위 기능 목록으로 확인되는 6개 외 나머지 2곳의 명칭·기능은 미정이며 임의로 추가하지 않는다. 지도 기본 그림과 위치가 맞는 수채화 컬러 오버레이를 사용한다. 장소마다 임의의 대표색을 부여하지 않고 기존 에셋 색을 따른다.

## 개발 순서

1. 하단 창·입력 통과·픽셀 표시·저장 및 플랫폼 POC를 검증한다.
2. 제작·판매·골드·재료·최소 탐험의 작은 반복을 완성한다.
3. 최신 기획인 마을 수리·호감도·상품 해금·피드백을 연결한다.
4. 플레이테스트 후 카드와 더 넓은 연구·무기 콘텐츠를 확장한다.

실행 방법과 지원 버전은 코드가 들어온 뒤 실제 검증 결과로 추가한다. 무료 3D 에셋을 최대한 활용하되, 배포 전 개별 라이선스와 출처를 기록한다. 저장소 공개 여부가 코드나 외부 에셋의 사용 허가를 대신하지 않는다.
